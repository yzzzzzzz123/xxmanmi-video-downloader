# 下载、片库交付与验证边界

仅在用户要求下载、整理片库或核对历史验证边界时读取。采集数据库任务不加载本文，也不因本文启动下载。

## 范围与默认值

- **全站模式（默认）**：用户说“采集小小漫迷”“下载全部资源”而未限定范围时，从 `https://www.xxmanmi.com/` 的实际公开入口遍历分类、资源线路及分页；不是只采集首页。
- **指定模式**：用户明确给出节目、页面 URL、分类、集数/日期区间或 m3u8 URL 时，仅处理指定范围。可组合多个条件；边界不清会明显扩大下载量时先澄清。
- 默认片库：解析当前桌面的 `小小漫迷.lnk`，使用其实际目标目录。当前用户约定目标为 `<用户指定的片库目录>`，每次仍须读取快捷方式核实；不要用桌面同名文件夹代替，也不要修改快捷方式指向。用户本次明确指定的目录优先；快捷方式不存在且没有已确认目录时，先明确存放位置，不沿用其他机器的绝对路径。
- 片库只交付原视频和系列/季目录。下载工作目录必须位于片库之外，调用脚本必须显式传入 `--output <工作目录>`；manifest、观察记录、临时媒体和诊断产物都属于工作目录。FFmpeg、虚拟环境和辅助脚本使用 Skill 私有目录或既有系统环境，不安装到片库。
- 本 Skill 的加载本身不启动采集或下载。用户只要求修改 Skill、查看状态或做 PoC 时，执行该范围，不创建采集子 agent；PoC 默认一集，不随后自动启动全站任务。
- 只处理正常可访问的未加密点播 HLS。不绕过登录、验证码、付费、DRM 或浏览器安全提示，不伪造凭证。

## 执行顺序

**主流程：站内搜索 → 同标签进入节目详情 → 右侧开发者工具检查当前 DOM 的 `data-web` → 保存分集队列 → 直连下载并校验。分集按钮是播放入口，不要点击分集或播放按钮来采集、验证下载链接。**

1. 首次采集或继续浏览，先阅读 [CUA 工作流](cua-workflow.md)。按当前浏览器工具文档使用 CUA 导航，并通过 Elements、只读 Console 或工具提供的受限只读 DOM 接口检查当前已打开页面；不要另起 Playwright、requests 抓站点 HTML 或隐藏接口。
2. 首次调用下载脚本，先阅读 [队列与命令](queue-contract.md)。确认片库与工作目录分离，检查工作目录的 `manifest.json`、两处磁盘剩余空间和 FFmpeg；不要覆盖已有文件或默默切换任务范围。
3. 在一个任务标签中打开首页/指定页面，复用已打开的右侧开发者工具；逐页提取实际出现的资源链接与分集 `data-web`。进入节目详情与点击某一集播放是不同操作，采集只需要前者。列表导航、资源导航均留在原任务标签；不批量打开节目标签。
4. 每完成一个列表页、资源页或指定分集批次，就持久化发现记录/分集队列。页面在改变前先保存所有已发现的链接。任务中断后从 manifest 的待访问项与未完成分集续跑。
5. 发现与下载交替分批进行，下载单并发。辅助脚本只接收 CUA 已观察到的 URL，不自行访问站点 HTML，不会因为命令名为 `run` 就完成全站发现。
6. 当前队列下载结束后，全站模式继续访问未覆盖入口，直到真实范围耗尽或遇到停止条件。队列为空不等于全站完成。

## 下载与暂停约定

- 优先量子；同一资源页、同一分集标签的其他已观察线路作为备选。相同 URL 与已验证文件去重；不同节目不要只凭“第 1 集”等标签合并。
- 每集完成立即保存 manifest。续跑跳过内容哈希一致的已完成文件；未完成单集从头下载，不声称支持 HLS 字节级断点续传。
- 保留 **10 GiB** 空闲空间，启动前和下载中检查；触线暂停并保留队列及 `.part.mp4`。除非用户明确要求，不自动降低阈值、不删除视频腾空间。
- 不设整个任务的固定超时。网络读超时 20 秒、FFmpeg 无媒体进度 180 秒视为单次失败；每集每次执行最多尝试 3 次（首次加 2 次重试），之后记为失败并继续其他集。再次重试失败项需显式 `--retry-failed`，不无限循环。
- 仅下载子进程禁用代理；不修改系统、浏览器或全局 shell 代理配置。
- 首个成功分集完整解码验证；所有分集都检查 FFmpeg 结果、视频流、成片时长与 HLS 时长、文件大小和 SHA-256，成功才发布为最终 MP4。加密、直播、外置音轨 master 等不支持的类型记明原因，不输出假成功文件。
- 未知同名文件、软链接、内容已改变的已完成文件保留原样并记冲突。只可重建 manifest 明确拥有的未完成 `.part.mp4`。
- 若资源内容、链接读取或媒体请求本身被验证码/登录/权限限制阻断，保留原标签与队列，请用户处理。误点播放后出现的验证码弹窗，应先退出误开的播放流程，不能直接认定已公开的 `data-web` 链接也需要该验证；不修改验证逻辑、伪造凭证或绕过实际访问限制。
- 用户关闭或持续操作任务标签时暂停浏览，不抢回焦点或反复新开标签。用户已授权自动补齐环境时，缺少依赖或 FFmpeg 不可用应按运行说明安装、修复并验证；仍无法解决或磁盘不足时明确报告。

## 进度与交付

中文进度说明本次范围、当前页/节目、已完成集数、失败数、下载容量和下一步；长任务约每 5 分钟汇总一次，交互平台要求更频繁时遵从平台。

结束时报告实际片库目录、模式、已发现/已访问页面、成功/重复/失败/未处理分集及暂停原因。只有覆盖记录 `exhausted=true`、无待访问/失败页面且当前分集全部完成或有效去重，才能称该范围完成。缺片和失败原因写在回复中，不额外生成片库内的清单、报告或续跑脚本。

## 片库结构与交付清理（用户默认要求）

- 电影按 `片库/系列名/片名_原画质或版本.mp4` 存放；单部电影可用片名作为目录。电视剧按 `片库/系列名/第几季/剧名_第01集.mp4` 存放。只为实际存在的视频保留目录，不保留每片一层的资源 ID、线路编号目录或重复的“片库/小小漫迷”嵌套层。
- 保留视频内容和原有清晰度，不为整理目录转码、压缩、改帧率、加水印或生成预览。HDTC 等版本标记如实保留。同名文件先核对内容；不同内容保留可区分的版本名，不覆盖、不只凭片名删视频。
- 交付只接收已完成并通过完整性校验的成片。`.part.mp4` 和失败状态不代表完整视频；先核实文件与失败原因。可能包含完整画面的唯一文件不得直接按后缀当垃圾删除。需要修复时在片库外的隔离副本验证，视频数据一致且原完整性检查通过后才发布。
- 整理前列明保留视频与目标路径，确认没有活跃下载写入。移动同盘文件后核对路径、数量和大小；跨盘复制或删除重复视频前核对 SHA-256。未知文件、唯一视频、同名冲突和越出目标目录的链接必须先查清，不能被批量清理吞掉。
- 正常交付后清理本任务产生且已无用途的 manifest、JSON/Markdown 清单、日志、观察记录、续跑脚本、锁、下载残片、诊断副本、缓存及空目录；这些文件不得留在片库，也不另建隐藏备份目录长期保留。用户明确要求整理既有片库时，同样清理其中已核实多余的 `.runtime`、`.tools` 和旧辅助文件。
- 下载仍在进行或明确暂停等待续跑时，只在片库外保留必要工作状态；正在使用的环境不删除。任务完成或用户明确结束并要求清理后，移除本任务的临时工作产物。共享工具保留在原来的 Skill/系统环境中，不复制进片库。
- Windows 清理只在已解析并核实的目标目录内使用原生文件操作；核对最终绝对路径和链接边界，先保全视频，再删已确认的辅助文件和空目录。若工具或权限拒绝清理，报告具体残留，不能把“已整理视频”表述为“已全部清理”。
- 最终验收：快捷方式打开的实际片库中只剩系列/季目录和有效原视频；没有额外报告、工作环境、残片、重复诊断视频或空文件夹。后续新增电影默认沿用此结构，无需用户再次说明。

## 已验证边界

当前站点已观察到 `/video2/<数字>.html` 资源页，以及分集元素的 `data-web` m3u8；这些是观察结果，不是猜测其他资源 ID、分页地址或线路结构的依据。已观察首页有多个分类/线路和 20 个节目链接；20 不是站点总量。

2026-09-25 的实测样本为《百家讲坛》20251202、资源页 `/video2/119740.html`：链接提取、CDN 直连和下载脚本在隔离目录验证。583 个分片生成 216,441,506 字节 MP4，时长 2327.18 秒，完整解码通过；实际中断、续跑、容量阈值暂停以及 20 项本地回归通过。

同日《爱情公寓第一季》资源页 `/video2/3175.html` 已验证站内搜索和当前 DOM 提取：第 01–20 集各有一条量子 HLS 和一条“下载”MP4，共 40 条地址、20 集。地址来自逐项读取的 `data-web`，不能靠点击播放或按编号补造。Windows/WSL 中更换为 Ubuntu FFmpeg 6.1.1 后，第 01 集生成 421,044,878 字节 MP4，时长 2767.67 秒，完整解码通过；首集验证不能代替其余分集的完成记录。

完整的同标签逐页点击链和全站分页穷尽尚未实测（测试标签被关闭）；首次执行必须先用当前界面验证导航和真实分页，再扩展采集。不要把规范中的遍历方法描述成已完成的全站实测。
