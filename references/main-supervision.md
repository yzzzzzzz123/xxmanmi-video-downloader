# 主线程：无日常播报的短监督入口

## 正常职责与单次入口

一个业务主线程监督原有01–04四路luna/medium。健康线程自行采集、入库、审计、封面和ack；主线程不代采、不代收批、不新增第五路。保留真实UUID、owner、目录、工具句柄和原宿主关系，idle/notLoaded、排队或短暂无日志不证明死亡。原宿主的正式协作入口仅定向恢复真正中断的原线程；健康线程不重复唤醒。

用户明确指定“当前线程就是主线程、旧业务主不再使用”时，由当前真实线程执行`recoveryctl.py adopt-main --authorized --thread <当前真实UUID> --request-id <本次明确用户请求ID>`。程序只在已核验停工、写闸关闭时移交main/policy并留历史，不替换四路或原中继。再以当前真实主ID执行`resume`开始用户明确要求的新周期，旧周期完整保留；不继续唤醒旧业务主。当前用户主线程没有原生Goal时不擅自创建，恢复回执如实标记`explicit_current_user_main`；不得据此宣称自动唤醒已成立。原宿主仍只做中继，Goal保持paused，处理定向指令不接管业务监督。

用户要求采集继续、优先安排空闲槽位时，先由原宿主定向续派空闲原线程，旧业务主停止新增调度并等待自身工具终态。可在上述`adopt-main`命令加`--live-handoff`完成只移交主身份：程序必须核验旧主原生回合已终态、无活动Goal或后台命令，项目未暂停且故障未超时。此路径保留原运行周期、首次故障预算、四路owner及开放写闸，不调用`resume`、不重置预算、不制造一小时超时来满足停工条件。移交完成后真实阻塞送新主，健康采集者不重复唤醒；任何门禁拒绝均保留原状态。

每次原生Goal续跑或实际故障事件先执行一次：

```powershell
python -X utf8 -B scripts/collection/operationsctl.py pulse --thread <真实主线程UUID>
```

pulse程序检查持久故障预算并补启动待办增量同步，输出短JSON，不调用模型。必要落主断点用同CLI的checkpoint命令持锁解析后原子保存；不要手改正在被四路读取的大型state.json，避免格式错误或半写读取。没有异常直接继续现有职责，不读取全历史、不广播询问四路、不循环空等。正常采集和故障修复期间只显示`working`，不播报修复日志、进度或技术细节；正式证据和回执继续保留。主线程维持实际执行，不以回复状态后退出代替监督。原小时/三小时报告均取消，旧送达水位只作历史，不重发。用户主动提问按该次请求答复。

用户侧不播报不影响内部故障送达：采集者只将真实阻塞或同步异常定向交给正式状态登记的当前业务主线程；旧宿主仅作必要中继，不替代业务主。正常成功不发送逐批通知，也不等待主线程催促。当前业务主等待实际工具终态或原生任务事件，再执行对应恢复，避免靠反复读取健康线程维持监督。主线程只做恢复和最小监督，不查榜、不准备关键词、不做分类或系列归组。

不新装监督服务、计划任务、后台模型轮询或永久同步daemon；复用已验证的宿主原生Goal续跑与提交事件。有界隐藏CLI一次最多处理四包后退出。没有实际宿主唤醒证据时，不能声称硬实时一小时截止已成立。

## 故障：先模板，再必要修复

先读[固定恢复模板](recovery-templates.md)，由recoveryctl匹配真实错误，只展开返回的精确参考。正式workflowctl错误自动记账；直接浏览器错误由原owner记录一次真实工具ID和错误。普通无资源页按有界失败保存后继续；正常已核实写锁等待不是死亡；未知动作只等原句柄，绝不重放、改nonce或伪造DOM。

用户已长期授权主线程对既有工作流故障做必要的最小源码修复，不逐次询问。修复后原线程立即从原断点续跑，不运行项目回归测试；语法/参数检查、去重、写锁、独立封面、审计、ack和生产验收保留。不扩张到新功能、依赖、结构、系统配置或应用部署。兼容旧线程已加载模块，原任务和证据不覆盖；确认死亡才调用清理Skill同槽补位，不定时轮换。

已认领且未采集的条目被误拼独立HD状态时，实际主线程可用`workflowctl.py repair-detail-title --thread OWNER --batch BATCH --evidence 本人节点证据 --source-tool 原生只读DOM工具ID --logs-stopped`。入口核验原owner最近两回合的真实DOM结果、独立标题文本和HD段落、同URL详情标题、原任务书与未变日志，持锁只修正该item并保留原值和证据哈希。原线程再`claim-detail`刷新剩余输入；不改详情标题门禁，不伪造failed、采集或ACK。

同一入口也仅接纳已证实的`&amp;`转义层级差异：证据沿用`detail-title-source-evidence/v1`，指定`correction_kind=html_entity_escape_layers`、原`original_title`、`failure_source_tool`及原生成功只读回执完整`inspect`对象作为`fresh_detail_public_dom`，`formal_current`如实记录`capture_attempted=true/capture_journaled=0`。程序绑定原生业务失败的精确标题错误及零落盘、限定真实只读查询结构，最多解码四层完整`&amp;`后要求非空题名逐字相等，核验原owner/parent/cwd/work、同URL及未采集锁门禁，再写入真实`#video`原始标题；保留状态、原item和证据，不放宽详情匹配，也不把标题修复当作采集或故障恢复。

唯一自动停工条件是任一采集槽位真实连续故障超过3600秒仍未恢复。首次故障时间跨重试、回合和替换身份保留，新的真实ACK或原任务搜索提交才能解除。10000是里程碑，单批结束或队列暂空不是采集停工条件；用户明确暂停/停止仍优先。规范修改时保持已有暂停状态，不执行pulse、恢复线程或同步生产。

超限后程序先关闭共享写入口，保存已完成数据、日志、未完成批次、搜索认领、事件队列和冻结包，再通过官方app-server接口暂停登记主线程、四路和原宿主的Goal并中断在途回合。用户已明确授权强制终止所有本项目采集执行：`recoveryctl.py stop --authorized --thread <真实主线程UUID>`内的`process_stop.py`使用官方接口终止所属采集后台命令，并锁定核实PID、启动时间、可执行路径、精确owner后的专属进程句柄强制结束。命令行不落盘或回显；共享app-server、桥接/MCP、浏览器、数据库、网页服务、用户应用和其他项目保留，不按名称或父进程树批杀。当前停工驱动完成正式回执后退出，不生成或发送用户报告。

必须核对Goal/turn实际终态、后台命令消失和专属进程退出，不把interrupt/terminate受理说成全部停止。`recovery-current.json`保存`thread_stop_receipts`与`process_stop_receipt`；任一终止失败，`stop_complete=false`，写入闸保持关闭，后续正式安全点可续核验，不能自动恢复或重放未知动作。正常、修复和停工均不向用户汇报，只保留最小`working`状态；旧报告水位和回执保持历史，不补发报告、不自动重启或删除证据。截止复用正式CLI/原生Goal安全点，不承诺未经验证的硬实时唤醒。

## 生产：提交事件，不逐批思考

按[统一节目对齐](all-catalogue-sync.md)及[节目同步Skill](../skills/manying-production-sync/SKILL.md)，正式数据库提交和封面收尾投递去重版本事件，主线程授权的单一隐藏CLI冻结固定节目范围、备份、事务合并、哈希核对和独立验收。正常同步不调用模型、不等待300个节目；失败保留原包，有界退避后由事件/pulse续跑。只读queued/pending不是生产完成；delta回执只证明所列ID，不冒充全库一致。用户要求全库校准才走手动全量入口，暂停采集不因单独同步而恢复。

保存什么同步什么：包含空、raw、失败、死记录、旧补源与已有分类，网站仍只展示健康节目。生产账号、会员、会话、收藏/观看/活动等不被本地覆盖。旧100/300轮和全量基线回执保留历史，不伪改、不重置。仅节目同步不部署应用或重启网页服务。

## 直接采集与数据保留

01–04先续原owner断点，再通过本人已观察的公开列表、实际来源和真实分页补充详情URL。详情经唯一共享队列独占认领，完成采集、审计、独立封面和ack；内部上报复用正式事件与回执。主线程不代采、不代收批，不创建关键词、榜单发现、分类或系列归组任务。

采集规范已删除分类入口、执行步骤和新分类字段写入要求，不存在待开启的分类开关。实际来源、线路、分集和媒体格式属于资源身份，继续如实保留。已保存的节目、资源、分类、系列及关联、用户数据、任务、证据和回执均保持原样，不归档、迁移、删表或改写历史记录。

历史搜索任务仅按原任务书和原claim恢复或安全收尾，不改原query、owner和未知动作，不以旧待办、缓存或缺表重新启动分类或关键词供给。规范修改不改网站或分类程序代码，不变更采集登记、不联系或恢复已暂停线程、不发布生产。

同任务未变Skill复用；只读短断点和精确真实回执，工作路径从正式JSON解析。只保留必要的任务、证据、断点和验收，不写临时脚本、重复快照或额外报告文件，不安排定期垃圾清理，也不重试用户取消的旧删除清单。后台程序隐藏启动，保护用户和他人标签、共享Chrome、数据库及所有在途证据。
