# 唯一 agent 的持续执行

当前 agent 同时负责 Playwright 采集、资源入库审计、独立封面、ACK 和受控生产增量验收；没有采集子线程、四路槽位或额外管理 agent。入口见[短流程](low-token-workflow.md)。

用户要求开启或继续任务时，复用当前线程原生 `/goal`，目标明确为单线程每日稳定增量更新。修改目标使用正式原生接口并保留 Goal 创建时间、用量和身份；不能将已替换的四路目标伪报完成。只改规范或只读状态时不恢复暂停。

旧四路迁移只用 `single_agentctl.py migrate --authorized --thread OWNER --request-id 实际用户消息ID`：先由正式 stop 完成旧 Goal/turn/专属进程停工，保留旧 owner、任务书、日志、未知动作和历史；迁移时写闸保持关闭。旧 ready 批次由当前 agent 按正式交接清单重新审计、检查封面并以自己身份 ACK；未完成 claimed 批次保留原批次及证据，用明确交接记录将已观察 URL 转交当前 agent 重新认领。任何一次状态写入失败均保持关闭，不手改协调 JSON。

用户同时授权继续运行时，正式 `recoveryctl.py resume --authorized --thread OWNER --request-id 实际用户消息ID` 复工，原停止周期完整保留。实际 Goal active 和共享写闸打开后才运行 `single_agentctl.py run`。旧宿主与旧采集者保持停止，不删除其会话或工作目录。

每个有界步骤先检查停工门禁和生产事件，然后采集/审计/封面/ACK。按照 CLI 返回续同一 claim/原句柄；空队列则继续实际来源发现，轮次完成按持久断点等待变化，不循环空领。一次有界 CLI 退出只是步骤完成，agent 的 Goal 和执行不得因此退出。

生产只有既有单一隐藏事件同步 CLI 可以写节目与资源数据，使用暂存、备份、事务、哈希和独立生产验收。保护生产账号、会员、会话、收藏、观看和活动数据；不部署网站应用。

正式停工保留连续第 7 个节目封面失败与真实故障 7200 秒两项独立门禁；关闭写闸、暂停 Goal、中断在途执行并精确终止已核实所属的采集程序和私有 headless 浏览器，保护共享 Chrome、MCP、数据库及用户应用。首次故障跨回合/重试保留，仅新的真实成功回执解除；封面失败次数只有真正取得合格封面才清零。不得自行复工。

运行、修复和停工仅显示 `working`，不发周期消息；用户提问时据实回答。没有新增 Windows 服务、自启动或计划任务，未来每日更新依赖原生 Goal 当前获授权并真实运行，不能宣称已安装定时调度。
