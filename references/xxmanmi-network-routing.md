# 小小漫迷直连规范

用户已确认并要求写入 Skill：所有现有及今后新增或恢复的采集线程（覆盖 `01`–`04` 全部槽位）默认启用浏览器 TUN 模式，访问 `xxmanmi.com` 和 `www.xxmanmi.com` 时按精确域名规则走 `DIRECT`；所有 agent 取封面时，中央 worker／本地 relay 对实际已核验媒体域名的请求也默认走 `DIRECT`。主线程统一维护这两个站点域名及取封面所需实际媒体域名的出口，保留系统代理开关、地址、无关域名规则和既有代理出口。在已授权的封面工作中执行此默认规则，无需再次询问；不扩展到无关域名，也不因修改规范恢复已暂停采集。

## 范围与正式规则

浏览器（Chrome）流量继续使用 TUN 入口，`xxmanmi.com` 与 `www.xxmanmi.com` 在代理核心内按精确规则选择 `DIRECT` 出口；入口与站点出口分别保留，不得为实现这两个域名直连而关闭 TUN。

取封面同样保留 TUN，以 `DIRECT` 作为实际媒体请求的出口。直连范围从本批已核验入库资源，以及经原公网校验允许的真实重定向、子播放列表和分片引用中确定；新增域名由主线程统一维护精确规则，采集者不并发改共享代理配置，不猜域名或绕过原认证与逐跳公网校验。不能仅将两个 xxmanmi 页面域名设为直连，就认为媒体请求也直连。

使用精确 `DOMAIN` 规则，并放在会提前匹配的规则之前：

```yaml
- DOMAIN,xxmanmi.com,DIRECT
- DOMAIN,www.xxmanmi.com,DIRECT
```

对取封面所需的每个实际媒体域名增加对应的 `DOMAIN,实际域名,DIRECT`，同样放在原代理 `MATCH` 回退之前；这不是固定两条 CDN 的白名单，后续资源沿用相同默认。`fake-ip-filter` 只控制 DNS 是否返回真实 IP，`trust_env=False` 只影响应用环境代理，两者都不能证明 TUN 出口为直连。

不要改为 `DOMAIN-SUFFIX`、全部中国站点直连、全局直连、关闭系统代理或修改代理服务器地址。其他浏览器与其他站点仍沿用原路由。凭据、订阅网址、完整节点配置和控制端口认证信息不得写入项目、日志、Skill 或聊天；运行时仅从现有本地配置在内存中读取。备份留在代理应用原私有配置目录内，不复制到项目仓库。

## 诊断与修复

先保留真实 owner、独占标签、当前任务书和已落盘证据。`ERR_CONNECTION_CLOSED` 等浏览器连接错误属于环境问题，不能标成节目 failed/skipped、不能取消健康线程或重放结果未知的搜索动作。没有可读取页面时不新领无法执行的批次；已在途的有效观察照常保留断点。

由主线程统一修复共享路由，采集线程等待通知，避免四人同时修改代理配置。可读取当前代理开关、监听、DNS 与代理核心状态，必要时比较直连和经现有代理的 TCP/TLS 握手；这些检查不提取网页，也不授权 HTTP 抓站点、隐藏接口、猜 URL、播放取链或绕过网站权限。

Clash 全局模式忽略域名规则。不能只添加规则就宣布生效，也不能直接切换到既有规则模式而改变其他站点行为。需要规则模式时，先保存当前全局所选出口，并在上述站点及媒体域名的精确 `DIRECT` 规则之后、原规则列表之前设置指向同一出口的 `MATCH` 回退，使其他流量仍走原出口；原规则列表、节点及分组保留。若当前出口无法安全保留或配置与实际核心不一致，保留断点并报告具体限制。

修改前保留可恢复备份，核对原文件未被并发修改，并用当前代理核心的配置检查入口验证候选配置。通过现有本机认证控制通道加载，凭据不进入命令行；不重启用户应用、不弹出辅助窗口。加载失败或验收不符，恢复同一份备份与原运行配置。不要修改订阅源内容；订阅更新、切换配置或代理重启后重新核对这两条规则，不能把一次内存加载当作永久有效。

## 验收与恢复采集

必须确认：

- 运行核心确实优先匹配两个精确域名 `DIRECT`，持久配置保留对应规则；系统代理开关、地址与其他流量出口均保持原值。
- 核对 Chrome 的实际连接确实经 TUN 入口，且运行核心已加载上述两条精确 `DIRECT` 规则；不能仅凭 TUN 开关或磁盘上的候选配置判定生效。
- 取封面还须核对实际媒体请求的连接记录命中对应精确域名、出站链为 `DIRECT`，并通过托管服务 PID／源端口等关联本次请求。未捕获连接时如实记为未证实，不能拿已加载规则代替实际出口。403 先区分代理路径与直连结果；播放列表 200 不代表视频解码、封面质量或 ACK 已通过。
- 原规则列表和其他配置保留，配置检查通过，经现有代理访问目标域名的 TLS 握手成功。涉及重载时复核重载后的实际核心状态。
- 至少一个采集线程在自己的批准浏览器标签中实际打开小小漫迷，读取当前公开 DOM；只有握手成功不能证明采集已恢复。
- 通知同一批健康的 `01`–`04` 线程自主续跑。丢失标签时在原 browser binding 内新建自己的标签；已落盘页不重采，搜索动作不重放。

恢复后沿用正式 `claim-detail` / `claim-search`、采集、入库审计、中央封面门禁和 ack 链路。以新批次的真实观察和核验证据确认进展，不把网络修复、队列入队或浏览器页面打开计为采集完成。
