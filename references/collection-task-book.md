# 持续采集任务书

日常详情任务书由 `workflowctl.py claim-detail --thread OWNER --limit 4` 生成；同时固定日志起始偏移、保存本批 `capture_input` 并返回仅未采项。续跑复用原 taskbook，不要求 agent 逐字段重写。以下合同用于理解异常或其他任务类型，标准调用见 [低 Token 工作流](low-token-workflow.md)。

项目 `SKILL.md` 定义 10,000 节目的长期目标；本文件定义每次交给一个 agent 的**有界任务书**。固定规则只维护在 Skill 与本参考中。每轮在 `Datebase/xxmanmi-resource-db/.runtime/collection-task-books/` 新建一个 UTF-8 JSON 任务书，文件名使用唯一 `task_id`；该目录属于片库外工作状态，不提交到 Git。不要把多个轮次的分工、结果和新指令持续追加到同一个 Markdown 文件，也不要把整库待办复制给子 agent。

## 任务类型

| 类型 | owner | 有界范围 | 完成证据 |
| --- | --- | --- | --- |
| `detail` | 一个参与 agent | 已观察 URL 列表，或从唯一共享队列最多领取 4 个详情页 | 停写日志、逐页结果、数据库核验、captured 项封面回执；正常完整收批的真实 `ack`，或正式入口记录的无封面待补与可接续结果 |

主流程只负责恢复和最小监督，不创建关键词、榜单发现、分类或系列任务。01–04直接观察公开列表、实际来源和分页，把真实详情URL交唯一共享队列去重、独占认领，再完成详情采集和验收。原有搜索任务只按原任务书、原claim和原证据恢复或安全收尾，不扩成新的关键词供给流程。

采集者执行已认领任务，各任务分别保留claim、来源、结果和进度，浏览器按原单lane执行，内部上报复用正式回执。任务书不增加分类、类型标签、国家、作品形态或系列归属字段；页面导航条件仅用于访问。实际来源、线路、分集和媒体格式是资源身份，继续如实保留。

先续本owner未完成批次；仅真实未迁移范围冲突时查旧 `coordination-request.md`，不每轮加载历史。任务书只属于一个owner，换代按正式交接创建关联续接任务书，不改旧owner、原query或历史证据。详情状态与搜索claims仍是权威，不建竞争队列。本次规范更新不创建、重派或改写真实任务，不恢复分类、调整登记或数据库。

## 必填字段

```json
{
  "task_id": "本轮唯一且可追溯的 ID",
  "kind": "detail",
  "owner": "当前参与 agent 的稳定身份",
  "created_at": "ISO 8601 时间",
  "objective": "本轮能核验的具体结果",
  "scope": {"channels": [], "observed_urls": []},
  "limit": 4,
  "work": "片库外本 owner 的绝对工作目录",
  "inputs": ["共享状态或实际观察的详情URL输入路径"],
  "acceptance": ["本轮必须产生的可核验输出及其检查方法；detail 还含 captured 项封面回执"],
  "stop_conditions": ["权限/验证码阻断", "范围完成或达到本轮上限"],
  "coordination_state": "唯一共享 state.json 的绝对路径"
}
```

上述示例为新详情任务。`scope` 只填当前任务实际需要的字段；不知道URL时写明共享队列独占claim条件，不猜地址。`limit` 不能突破浏览器限制或单lane约定。任务书引用已有证据路径，不内嵌整库标题或媒体地址；交付前核对owner、范围、共享认领和已分配工作是否重叠。旧任务书与搜索claims保持原样，必要收尾见[历史搜索恢复](search-workflow.md)。

## 完成、阻塞与续跑

执行者保存任务书ID、batch_id、逐页结果、核验/封面回执、阻塞与下一步；普通成功只落程序计数，真实异常定向内部交主线程，不逐批广播。正常、修复和停工均不向用户汇报，只显示`working`；用户主动询问按该次请求答复。完整原始观察留自身目录。详情经入库/审计后由独立中央worker在全局锁内生成或核验合格真实帧，已有封面也验证。正常完整收批须 captured 项全通过并写真实回执后才 ack；raw/failed/skipped 不要求封面，不得把已采节目改为这些结果来绕过门禁。

单节目已确认实际 `DIRECT` 且有界候选、窗口与质量/去重门禁耗尽仍无合格封面时，按[封面恢复规则](cover-recovery.md#单节目无封面与连续失败停工)保留资源、批次、证据和真实待补状态，可经正式入口跳过并接续其他节目，不删除节目或假报完成。四路合并按中央实际处理完成顺序统计不同节目，第 1–6 个连续无封面可跳过，第 7 个立即全局关闭写闸并强制停工，只有真实合格封面成功清零；同节目重试、raw、换批、换 owner 或重启不得冒充新节目或重置计数。系统或未知工具故障仍走原恢复流程。

当前 CLI 尚未支持该待补跳过及全局计数机制；主线程须先适配正式收批入口，适配前保留原批次。不得手改 ACK、verification 或状态、编造跳过参数，或借规范修改恢复采集。只有正式入口如实记录逐项结果、确认可接续且未触发全局停工时，才继续领批。

## 有界上下文与轮换

任务持久，只有确认原采集线程死亡才按 [长期运行规范](unattended-lifecycle.md)调用清理Skill，核实未知工具、日志停写与正式交接后补位；定时轮换删除。不全量继承/fork旧聊天，不把所有历史任务书/报告塞给新agent。交接摘要只引用本任务、剩余范围、日志偏移/哈希、绑定与回执；新会话先与权威状态复核，不把摘要当写入许可。原任务书与核验记录不覆盖，重试预算不重置，补位不标记10,000目标完成。

进度写入既有协调状态、数据库和批次证据，不反复改写旧任务书。会话中断时查找未完成任务书并对照 `coordctl current/status` 与工作目录，从原owner断点继续；完成或受阻后，新工作使用新ID和任务书。10,000为核验里程碑，不是自动停工条件。详情队列不足时由采集者沿实际公开列表、来源和分页继续观察真实URL；无法继续时保留断点和真实阻塞，不循环空领、不猜链接。已有数据和采集暂停状态保持原样，规范修改不自动恢复采集。
