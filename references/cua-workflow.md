# CUA：发现页面与分集

## 建立任务标签

使用本轮可用的 CUA 入口；首次调用只执行工具说明允许的初始化调用，阅读返回文档后继续。发生上下文压缩后按工具要求重读文档。原生 Chrome 控制与 CUA 浏览器接口均可，但实际操作要遵守当前接口的限制。

当前 Chrome binding 的完整接口从其 `browser.documentation()` 读取。长文档显示截断时，保留真实返回字符串，只输出 `interface PlaywrightAPI` 等所需段落（如从 indexOf 位置 slice 1800 字符）；通用 CUA/Tab 摘要或未显示的片段不能证明 evaluate 不支持。已有明确 read-only evaluate 文档时，正式 prepare 代码使用该接口，不因模型没看到长文档中段而停工，也不为取文档重选浏览器。先读完文档再开始 metadata/分段链。

优先使用用户明确给出的站点标签，但借用不等于有权关闭。没有合适标签时，默认新建并复用一个本线程工作标签，不占用用户正在播放视频或其他线程的页面。01–04从本人已观察的公开来源、列表、分页与自然导航发现详情，主线程不查榜、不提供关键词或代采。各角色确需对照、诊断时可增加本人临时标签，记录真实owner、browser binding、tab ID、用途与是否本人创建。证据落盘且无在途动作后安全关闭已用完的本人标签，多标签不扩大单lane并发。每次输入前核对界面，用户改动后重新读取状态。

采集工作标签默认使用所属槽位的Chrome分组，名称只能精确为 `01`、`02`、`03`、`04`，禁止“01采集线程”、日期、节目名或重建后缀。宿主要求 `nameSession` 时同号命名；只处理本任务标签，不重排用户标签。组名不是标签所有权证明。

采用 DevTools 人工界面分支时，打开开发者工具并通过实际菜单选择右侧停靠；已有工具面板不要再次按快捷键把它关闭。已支持文档中的只读 Browser DOM 接口时，不为检查 DOM 再打开 DevTools。资源列表与资源详情都在此任务标签导航；不能批量新开资源页。普通点击若会 `target=_blank`，读取/复制界面中已出现的链接，在原标签地址栏粘贴并回车；返回列表同样使用已保存的真实 URL。不要通过修改站点事件、批量脚本点击或篡改 target 来猜测导航行为。

浏览器工具的截图可能只包含网页区域，不包含停靠在右侧的开发者工具。用户已经打开面板时，不要仅因截图看不到面板就反复按 F12。通过当前工具支持的只读 DOM 检查继续，不声称看到了截图之外的面板状态。

优先通过 Elements/可访问性树检查 DOM，必要时在已确认的 DevTools Console 中执行只读查询。若当前 Browser 工具提供受限的当前页面 DOM 读取接口（例如文档中的 `tab.playwright.evaluate`），可用它读取同一份已加载 DOM；只取页面元素、属性和文本，不发网络请求、不访问应用内部状态，也不另起 Playwright 浏览器。不要绕过“禁止粘贴”等浏览器安全提示。以下是查询形状，使用前确认当前页面确有这些元素。

浏览器交互和状态读取可能分别耗时。将它们拆成调用，或按工具文档设置足以容纳整段操作的超时；一次多步调用超时后，先核对实际页面和标签状态，不重复点击、不直接断言浏览器已断开。只在原标签确实不可用时恢复标签，不因句柄失效重做登录和插件安装。

本机原生 `cua_repl.js` 的正常单次往返已实测约 21 秒；采集中的单步浏览器调用使用 `timeout_ms=120000`，不要把外层工具截止缩短为 20 秒。页面操作自身仍使用有界超时，并将交互与后续状态读取分开。工具若返回 `js execution timed out; kernel reset, rerun your request`，其中“rerun”不授权重放点击：先保留原调用及未知结果，按当前工具文档重新取得只读状态和本人标签，确认实际控件与页面变化后处理原断点。新的超时设置只用于尚未执行的操作。

需要跨回合保留本线程工作标签或未持久化结果时，按当前浏览器文档使用受支持的 `tab.markHandoff()` 等保留机制，不假定所有接口都有此方法。已用完的本人临时标签在证据落盘且无在途动作后立即关闭；正在复用的主工作标签不每页/每批销毁，用户或他人标签不关闭。未保留标签可能被宿主回收；missing/stale时按真实绑定和断点新建必要替代标签，不重试失效ID或重放未知点击。输入只用当前文档允许的 `playwright.locator(...).fill(...)`，或聚焦后 `dom_cua.type(...)`；`dom_cua` 没有 `fill`。不定期重启浏览器或REPL；真实故障恢复须先核实原工具终态与影响范围，保护共享浏览器、健康线程和用户标签。

当前 Chrome 的 `locator.click` 不支持 `position`，传入该字段不能证明改变了实际点击点。自定义 radio 的零尺寸不等于禁用；跨行 label 的包围框中心也可能落在空白处。点击后状态未变时，先只读核对控件唯一性、`label.control` 关联、禁用状态、可见文字分段矩形及遮挡。确认真实可见位置后，按当前文档使用 CUA 坐标点击，再核验选中状态与列表；不得猜坐标、强制绕过、改写 `checked` 或派发事件。

## 列表发现

先记录当前列表 URL、页面条件（分类/线路/排序/页码）、所有可见节目链接以及下一页/更多入口，然后才进入资源页。可用只读查询辅助记录当前 DOM 中的链接：

```javascript
JSON.stringify(Array.from(document.querySelectorAll('a[href]'), a => ({
  text: a.textContent.trim(), url: a.href, target: a.getAttribute('target')
})))
```

识别真实显示为节目详情的链接；当前已验证形状是 `/video2/<id>.html`，遇到其他形状须实际打开一个验证，不把所有站内链接都当资源。去掉纯 fragment 进行去重，保留影响筛选/分页的查询参数。不要猜 ID 范围、拼接未知页码接口或扫描隐藏 API。

全站模式从首页实际存在的分类、线路、公开分页/加载更多进行广度优先发现。当前观察到分类为动漫、剧集、电影、综艺，线路包括量子、非凡、天堂、酷播等，但以后以当时 UI 为准，不以这份观察清单限制或虚构范围。

- 保存公开导航入口与发现的资源页到 `coverage.discovered`。
- 一个列表页的节目链接和后续入口都已读取并保存后，才记 `visited`。
- 点击实际“下一页”或“加载更多”；动态加载应观察 URL、页面标识和新增资源集合。URL 不变的多个 UI 状态，所有状态穷尽后才将该 URL 记为已访问，并在任务批次记录中注明筛选条件/终止证据。
- 若连续动作仅得到同一组链接，检查是否到底/按钮禁用/访问异常；不要仅凭一次空白或网络超时认定到底。
- 每个入口真实耗尽、无待访问页面、无无法解释的访问失败，才设置 `coverage.exhausted=true`。覆盖字段由 Agent 根据现场证据维护，脚本无法替代这个判断。

指定模式只发现匹配范围的资源：指定详情链接处理该页；指定节目使用站内实际搜索 UI 并核实同名/年份；指定分类只遍历该分类；指定集数/日期区间只入队匹配分集。用户给出直接 m3u8 时可跳过站点发现，以该 URL 作 `page_url`、用户标题作 `title`，默认标签 `视频`。

站内搜索要以结果列表更新为准。已观察到的界面是在搜索框填写节目名后点击“量子”等线路按钮发起搜索，仅按 Enter 不一定更新结果。核对搜索词、所选线路与新结果，不能把旧搜索结果当成本次结果。

若唯一一次已返回的搜索点击无法导出结果证据，但只读前后 DOM 均证明精确搜索词与线路仍显示同一个旧的非目标结果，可使用 `workflowctl.py abandon-confirmed-click-stale-non-target-result` 将该 claim 终结为 `manual_review`、`replay_authorized=false`。证据必须包含匹配 owner 的 live host、仍可读的原 tab、单次 action、完全一致的前后单结果、无本地 evidence/commit/journal、无写锁及相同的双日志快照。该入口只记录隔离审计，不写搜索证据、不提交、不入队；目标标题相同、结果不同、状态不明或任何条件缺失时必须拒绝并保留断点。

若原 task tab 已消失，且既存执行记录明确保存唯一一次已返回 click 及 helper 的精确拒绝错误 `Search results did not visibly change from the pre-action snapshot; inspect stale or identical results`，可使用 `workflowctl.py abandon-confirmed-click-helper-gate-error` 终结为 `manual_review`、`replay_authorized=false`。必须同时核实 live owner session、原 tab 的精确 No-tab 错误与不含该 tab 的 inventory、无 receipt/evidence/commit/task journal/写锁及稳定双日志。此入口不接受或补造 actionId/receipt、不写搜索 evidence、不提交、不入队；缺少任何既存事实都应保留断点。

## 资源页提取

标准详情优先调用项目 `scripts/collection/detail-capture.mjs` 的 `runDetailBatch`，通过已批准的当前标签执行这里的只读 DOM、分段计数和落盘规则，最短调用见 [低 Token 工作流](low-token-workflow.md)。模块不初始化浏览器，也不能替代当前选择器与权限核对；页面变化时才回到本节检查，不让每个 agent 重写同一采集器。搜索证据可复用 `search-evidence.mjs`，保持输入/选中渠道/分页及真实结果更新的门禁。

确认标题与页面 URL，先识别线路标签与集数列表。**停留在节目详情页读取链接，不点击“第 01 集”等分集或播放按钮，也不通过试播来验证下载地址。** 已观察的分集结构：

```html
<a class="episode" data-web="https://…/index.m3u8">20251202</a>
```

通过右侧 Elements、只读 Console 或当前浏览器工具的受限只读 DOM 接口，一次记录已加载的分集元素。可访问性快照只显示“第 01 集”等文字、没有 `href`，不代表不存在 `data-web`；必须检查实际 DOM 属性。下面的 `#list` 应先在当前页面确认，不能把示例选择器未命中等同于没有链接：

```javascript
JSON.stringify({
  page_url: location.href,
  page_title: document.title,
  episodes: Array.from(document.querySelectorAll('#list a[data-web]'), a => ({
    label: a.textContent.trim(),
    url: a.getAttribute('data-web'),
    group: a.closest('[class*="playList"]')?.className || ''
  }))
})
```

`page_title` 可能含站点后缀，应与可见节目名核对。`group` 只是 DOM 分组，不等于线路名；对照真实可见的线路标签后转换为入队字段 `line`，无法确定就留空，不猜“量子”。相对地址用当前页面 URL 解析，但只提交真实存在的 HTTP(S) 地址。

同一集可能同时有量子 HLS 和“下载”MP4，先保留全部真实地址与分组，再按分集标签和实际线路整理。例如两个来源各 20 条地址仍是 20 集，不是 40 集。当前下载脚本仅支持 HLS：优先将量子 `.m3u8` 入队，直接 MP4 地址另存观察记录，不把它当作已支持的 HLS 备选。

检查折叠、线路切换、分页或“更多集数”是否影响 DOM 内容。AX 的“显示 0–100 项”可能只是工具截断，不是实际总集数。**先单独读取 `document.querySelectorAll('#list a[data-web]').length`，再与实际返回和落盘的条目数比较。** 已实测页面有 2548 条时，一次浏览器 DOM 读取只返回前 2000 条，且未报错；长结果应按索引切成每段不超过 1000 条，只读提取并检查各段长度、首尾边界、总数和各线路数量。未完全一致不得入库；禁止根据首尾样本补造中间 URL。确认实际 DOM 没有 `data-web` 后，检查当前页面已经公开展示的媒体链接；仍无可用链接则记录缺失原因，不自行改成点击播放或猜 CDN 路径。

若误点分集后弹出验证码，退出误开的播放弹窗，回到详情页的只读 DOM 提取流程。不要把播放入口的验证自动扩展为公开链接下载的前置条件。若页面内容、链接读取或媒体请求本身确实受验证、权限或 DRM 限制，保留记录并请用户处理；不得修改验证逻辑、会话或凭证来绕过限制。

将规范化后的记录写入当前任务批次 JSON，再 `ingest`。成功入队后才标记该资源页已访问。已发现但未能读取的页面保留失败原因，继续其他不受影响页面；全站被验证码阻断时停止浏览并请用户处理。

## 封面帧边界

封面不是浏览器采集步骤。只有详情资源已完整核验并同步数据库后，收批链路才可把该节目交给独立中央封面 worker；worker 通过本地 relay 对已核验资源做有界解码并选择真实视频帧。不得为封面点击播放、从播放器取链、猜 URL，或回到站点补抓隐藏接口。

已有封面仍须按全库去重和质量规则验证。正常完整收批须封面通过并取得真实 ACK，不能用重复图、坏图或文字卡替代。单节目已确认实际 `DIRECT` 且有界候选、窗口与质量/去重门禁耗尽仍无合格帧时，按[封面恢复规则](cover-recovery.md#单节目无封面与连续失败停工)保留资源、批次、证据和真实待补状态，经正式入口跳过后可继续其他节目，不删除节目或假报完整成功。四路合并按中央实际处理完成顺序统计不同节目，第 1–6 个连续无封面可跳过，第 7 个立即全局关闭写闸并强制停工；只有真实合格封面成功清零，同节目重试、raw、换批、换 owner 或重启不得冒充新节目或重置计数。

当前 CLI 尚未实现该待补跳过和全局计数机制，适配前保留原 `ready/cover_pending` 批次，不手改 ACK、verification 或状态，不编造参数。raw/failed/skipped 不要求封面，但不得将已采节目改成这些结果来绕过门禁；系统、鉴权、数据库或未知工具故障仍走原恢复流程。浏览器线程只保留原有 DOM 证据，不承担封面写入、锁或完成判定，规范修改不解除已有暂停。

## 首次扩展前的小样验证

同一标签依次验证：列表→一个已观察详情→提取→返回原列表→真实下一页（若存在）。核实右侧 DevTools 仍在、链接没有丢失、分页确实产生新页面/数据。若用户关闭标签，不抢占浏览器；保存已有资料，报告未验证的部分。首次新线路仅验证一集下载再扩大该线路，失败只在临时目录调整方法，不先修改正式 Skill 试错。
