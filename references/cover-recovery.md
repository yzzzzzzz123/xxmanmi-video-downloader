# 中央封面故障修复

仅在真实封面故障时由主线程加载本参考；采集线程保留原 `ready` 批次和停写日志，不因修复重采详情或跳过门禁。

## 先区分资源不可用与候选遗漏

若多节目所有候选均立即 `decoder_failed` 且解码数为零，先用真实已核验资源 ID 有界检查本地 relay；不要逐节目重复重试。合法中央封面令牌请求若返回“没有找到这个节目”404，检查是否误把必须已有封面的公开展示门禁用于首次封面解码，形成循环阻断。仅经 loopback＋有效中央令牌认证的解码请求可使用当前数据库仍已采集、状态正常且 ID／节目／原地址绑定一致的支持资源；公开页面和普通媒体请求仍必须有合格封面，坏、死、未采节目继续隐藏。修复后只重载已核实身份的本地服务，并由原 owner 重入原 ready 批次。

从失败回执和中央审计读取 `attempted_source_ids`、解码数量、质量/重复拒绝及来源错误，再对照本节目已核验数据库资源。不能把前几集某一线路失败当成全部线路失效。

中央 worker 的候选仍最多八条，只接收真实持久化资源 ID 和对应 `/media/ID`；各实际线路轮流共享此上限，m3u8 优先，同一线路保持原分集顺序。不得扩大为猜测网址、站点抓取或播放取链。诊断只能通过已授权本地 relay 有界读取核验过的资源，媒体凭据和原始地址查询参数不进入输出。

## 已耗尽窗口的定向真实帧修复

资源、规则和窗口均未变化时不反复重试。同一真实片源已证明存在可用新窗口后，可在本机私有运行目录维护 `cover-sampling-hints.json`，不把机器配置写入项目仓库。

文件使用 `version: 1`，`programs` 按节目 ID 索引；每项只允许 `title`、`resource_id`、`window_start` 和可选 `crop`。标题和已核验资源 ID 必须与当前节目精确一致；新窗口起点为 0–21600 秒整数，使用一个最多 60 秒、五帧的有界窗口替换该资源已耗尽的窗口。修改前复核数据库绑定和真实诊断证据、保留已有配置及备份，发现并发修改即停止。

`crop` 仅用于实际画面主体被大面积暗背景影响的情况，格式为真实图像像素坐标 `[left, top, right, bottom]`，必须位于解码帧内且至少 200×100。先检查原始帧与全库封面的冲突，存在重复即不得裁剪；保留原像素，不添加内容、不合成细节、不拉伸放大。裁剪结果仍经过原质量规则和中央全库去重锁，文字卡、黑屏、劣质或重复画面继续拒绝。最终审计记录配置哈希、真实资源 ID、新窗口起点及实际采用的裁剪范围，旧失败审计保留。

经核实的0秒提示遇到实际时长小于原12秒采样间隔的短片时，中央worker先通过同一合法relay有界测量时长，再在原窗口内最多取五帧，避免只取到片尾文字卡。只有真实有限正时长才能缩短间隔，未知时长保持原采样；质量及全库去重门禁继续执行。选中审计记录实测短片时长与实际间隔，不把诊断帧直接安装成封面。

## 重载与验收

修改常驻组件时，先等已经发出的收批/封面工具自然终态，健康采集者在原批次安全点暂缓新封面请求。仅用 `web/manage.py` 的正式生命周期重载已核实身份的本地组件，隐藏启动；不批杀共享服务、不动生产或数据库。验收 HTTP、托管实例身份及该服务实际可见窗口后解除短暂停顿。

由原 owner 幂等重入正式 `complete-detail --logs-stopped`，中央封面逐项通过、verification 和 ack 均成功才恢复领批。诊断帧存在、离线测试通过或消息已投递都不能代替这个验收。清理仅删除本次诊断确切拥有的临时图像，不遍历删除其他线程产物。
