# 中央封面故障修复

取封面、处理无封面节目跳过或真实封面故障时按需读取本参考；采集线程保留原 `ready` 批次和停写日志，不因修复重采详情或绕过门禁。

取封面默认沿 `agent → 中央 worker → 本地 relay → 已核验媒体域名`，媒体出网走 `DIRECT`，浏览器及系统 TUN 保持开启。主线程仅对真实已核验资源及其合法响应引用的新媒体域名维护精确 `DOMAIN,<实际域名>,DIRECT` 规则；不猜域名、不扩大为后缀或全局直连，不改其他流量。已有授权封面流程按此默认执行，不增加重复确认；中央鉴权、公网 IP 逐跳校验、质量与全库去重、ACK 门禁照常执行，原批次、证据和暂停状态保留。

DNS `fake-ip-filter` 只影响解析，`trust_env=False` 不会绕开系统 TUN，两者都不能证明实际直连。先核对运行核心的已加载规则与媒体实际连接确为 `DIRECT`，再诊断片源；候选配置、HTTP 成功或有效 m3u8 都不能代替完整解码、封面质量及正式收批验收。

## 先区分资源不可用与候选遗漏

若数据库确认有资源，但中央回执为 `no_resources`，先检查这些已核验资源域名的系统 DNS。TUN 的 fake-IP（例如 `198.18.0.0/16`）会被公共地址校验正常拒绝，导致候选为空。此时在现用代理配置中备份并仅为实际受影响的域名添加真实 DNS 例外，复核系统解析为公网地址且原 TUN、站点直连和其他代理规则保留；不要放宽应用的私网拒绝规则或修改资源记录。网络条件修复后，由原 owner 重入原 ready 批次验证中央封面。

代理核心接受配置加载不代表客户端已选中该本地配置。通过控制器读取实际 `mode` 与生效规则，确认精确直连规则位于原代理兜底之前；全局模式会绕过这些规则。另核对客户端当前选中的配置及模式缓存，避免再次应用旧订阅后丢失修复。需要用户在客户端完成选中而当前窗口控制不可用时，先准备可导入的完整本地配置、恢复当前核心规则并验证真实回执，再明确交接选中步骤；不把临时生效说成持久设置已完成，也不输出控制器凭据或订阅地址。

若多节目所有候选均立即 `decoder_failed` 且解码数为零，先用真实已核验资源 ID 有界检查本地 relay；不要逐节目重复重试。合法中央封面令牌请求若返回“没有找到这个节目”404，检查是否误把必须已有封面的公开展示门禁用于首次封面解码，形成循环阻断。仅经 loopback＋有效中央令牌认证的解码请求可使用当前数据库仍已采集、状态正常且 ID／节目／原地址绑定一致的支持资源；公开页面和普通媒体请求仍必须有合格封面，坏、死、未采节目继续隐藏。修复后只重载已核实身份的本地服务，并由原 owner 重入原 ready 批次。

从失败回执和中央审计读取 `attempted_source_ids`、解码数量、质量/重复拒绝及来源错误，再对照本节目已核验数据库资源。不能把前几集某一线路失败当成全部线路失效。

中央 worker 的候选仍最多八条，只接收真实持久化资源 ID 和对应 `/media/ID`；各实际线路轮流共享此上限，m3u8 优先，同一线路保持原分集顺序。不得扩大为猜测网址、站点抓取或播放取链。诊断只能通过已授权本地 relay 有界读取核验过的资源，媒体凭据和原始地址查询参数不进入输出。

## 单节目无封面与连续失败停工

解码故障的默认顺序是先有界诊断和修复，再复验当前节目；仍失败时，通过正式封面待补入口跳过并继续后续队列。不能只提交修复建议后反复查同一状态，也不能在仍有可执行队列且允许正式跳过时把整个Goal标为blocked。相同故障不逐节目重复长诊断，沿用已验证修复；首次故障时间、失败审计和不同节目连续计数保留。第7个连续失败或真实故障7200秒仍按正式流程停工，数据库、鉴权、未知写入等非节目解码故障不冒充可跳过结果。

已确认实际 `DIRECT`，并且原有限候选、采样窗口及质量/去重门禁确实耗尽后，单个节目仍无合格封面时可以跳过该节目、继续其他节目。保留已采资源、原批次、原证据及 `cover_pending` / `unavailable` 的真实状态，不伪造封面成功或完整 `captured` 完成；网站仍不展示未通过封面门禁的节目。系统、鉴权、数据库或结果未知的工具故障继续原恢复流程，不能算作节目无封面。

全项目 `01`–`04` 合并按中央封面实际处理完成顺序，持久统计不同节目的连续无封面结果：第 1–6 个可跳过，第 7 个立即强制全局关闭写闸并停工，保留全部进度。只有真实合格封面成功才清零；`raw`、同节目重试、换 batch、换 owner 或重启均不得冒充新节目或重置计数。

正式收批入口必须逐 item 如实记录通过、无封面及保留断点，不能用原批次级 ACK 伪造整批完整成功。若现有工具暂不支持该跳过与全局计数规则，主线程先适配既有收批入口；适配前保留原批次，不手改 ACK、verification 或状态，不编造跳过参数，也不借规范修改恢复已暂停采集。

## 已耗尽窗口的定向真实帧修复

资源、规则和窗口均未变化时不反复重试。同一真实片源已证明存在可用新窗口后，可在本机私有运行目录维护 `cover-sampling-hints.json`，不把机器配置写入项目仓库。

文件使用 `version: 1`，`programs` 按节目 ID 索引；每项只允许 `title`、`resource_id`、`window_start` 和可选 `crop`。标题和已核验资源 ID 必须与当前节目精确一致；新窗口起点为 0–21600 秒整数，使用一个最多 60 秒、五帧的有界窗口替换该资源已耗尽的窗口。修改前复核数据库绑定和真实诊断证据、保留已有配置及备份，发现并发修改即停止。

`crop` 仅用于实际画面主体被大面积暗背景影响的情况，格式为真实图像像素坐标 `[left, top, right, bottom]`，必须位于解码帧内且至少 200×100。先检查原始帧与全库封面的冲突，存在重复即不得裁剪；保留原像素，不添加内容、不合成细节、不拉伸放大。裁剪结果仍经过原质量规则和中央全库去重锁，文字卡、黑屏、劣质或重复画面继续拒绝。最终审计记录配置哈希、真实资源 ID、新窗口起点及实际采用的裁剪范围，旧失败审计保留。

经核实的0秒提示遇到实际时长小于原12秒采样间隔的短片时，中央worker先通过同一合法relay有界测量时长，再在原窗口内最多取五帧，避免只取到片尾文字卡。只有真实有限正时长才能缩短间隔，未知时长保持原采样；质量及全库去重门禁继续执行。选中审计记录实测短片时长与实际间隔，不把诊断帧直接安装成封面。

## 重载与验收

服务器采集专用封面服务使用系统`/usr/bin/ffmpeg`，避免已验证会崩溃的随包二进制；仅对已鉴权loopback relay的HLS解码及测时使用`-extension_picky 0`，因为签名分片路由没有媒体扩展名。资源ID绑定、令牌、公网地址校验、有限窗口、图像质量与全库去重保持。服务器只重载`manying-collector-cover.service`，不改正式网站服务。

修改常驻组件时，先等已经发出的收批/封面工具自然终态，健康采集者在原批次安全点暂缓新封面请求。仅用 `web/manage.py` 的正式生命周期重载已核实身份的本地组件，隐藏启动；不批杀共享服务、不动生产或数据库。验收 HTTP、托管实例身份及该服务实际可见窗口后解除短暂停顿。

由原 owner 幂等重入正式 `complete-detail --logs-stopped`，核验中央封面的逐项真实结果及正式 verification / ACK：符合上述条件的无封面节目按正式入口保留断点并跳过，未触发第 7 个连续失败且入口确认可接续时才继续领批；不得把无封面项合并成整批完整成功。诊断帧存在、离线测试通过或消息已投递都不能代替这个验收。清理仅删除本次诊断确切拥有的临时图像，不遍历删除其他线程产物。
