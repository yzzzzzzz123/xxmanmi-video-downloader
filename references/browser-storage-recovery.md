# 小小漫迷站点存储配额故障

仅在公开资源列表异常且有实际浏览器错误证据时使用，不为正常页面额外读取控制台。已有故障特征是 `QuotaExceededError`，写入 `playHis` 或 `vl…` 时超过配额；这可能在资源列表初始化前中断页面，表现为标题正常、列表一直“加载中”。不能据此宣称资源不存在、全部节目失败或验证码阻塞。

## 恢复边界

- 原 owner 保留已成功落盘的页面、claimed/ready 批次和独占标签。主线程只暂停共享故障影响的新增浏览器动作；已发出的工具自然收妥，未知结果不重放。维护等待不等于用户暂停，不擅自改变持久暂停门禁。
- 保存精确页面、原 owner/batch、当前可见列表和有界控制台错误。读当前浏览器 Skill；禁止读取私有 cookies、localStorage 值、profile 或 session store。不要扫描其他站点存储、删除浏览器配置或重启共享浏览器。
- 优先核实站点公开的维护按钮或批准插件的文档化维护入口。入口缺失或精确维护命令明确不受支持时停止，记录未发生修改，不改用另一底层工具或脚本绕过限制。
- 站点数据清理可能同时删除站内观看历史、偏好或登录状态；没有可恢复的精确缓存入口时，先说明具体站点及影响，再取得用户明确操作/确认。清理范围须是本次故障的实际 origin；本次已实测为 `https://www.xxmanmi.com`，不能扩大到所有网站、浏览器历史或系统代理。用户已完成清理后不再重复询问或清理。

## 原断点验收

确认原工具已终态后，由原 owner 在自有标签核对精确详情 URL，做一次针对已解除环境故障的有界 reload，并核实标题、完整 `#list a[data-web]` 数量及实际线路。仅看 readyState 或进程存在不能验收恢复。列表正常后继续正式采集器，不重采本批已落盘页；完整入库、审计、中央封面门禁及 ack 仍由原 owner 执行。

已经收批为 `manual_review` 的受影响页，在故障解除证据存在后，由注册 peer 按 [协作协议](multi-thread-collection.md) 的正式 `coordctl retry` 对精确 URL 回队一次，保留原失败证据及重试次数；不能重复 enqueue、改写旧回执或直接计成功。再次失败保留断点并报告，不形成无界刷新/清理循环。

2026-10-04 的实际验证：原批次 001926 的第四页在用户完成单一站点清理后，一次 reload 恢复两条真实公开资源，原 owner 沿用前三页证据续采。该结果证明此次恢复，不证明已自动防止站点缓存再次增长，也不替代 24/72 小时无人值守验收。
