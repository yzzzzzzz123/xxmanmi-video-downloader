# 本地 RPA 观察与有界恢复

本文件替代旧的浏览器工具恢复方式。正常流程见[后台编辑](rpa-publishing.md)和[正式发表](rpa-publication.md)，都在本地rpa_session.py持续会话完成，不调用CUA或浏览器插件。文件名保留，避免已有链接失效。

| 问题 | 本地RPA处理 |
| --- | --- |
| 控件不唯一、不可见或文案变化 | observe、dom重新定位；弹窗选择器带:visible，后台可能保留多个隐藏旧弹窗 |
| 点击后未变化 | 等明确就绪条件后观察；对已确认的普通控件可用click的key:true正常Enter，不反复点最终提交 |
| 新tab未就绪 | 预先用new_page:true/expect_page绑定，等DOM及正文可见，不靠固定sleep后立即读title |
| .ProseMirror严格匹配失败 | 标题、正文分开定位，标题获得style后不能用[style]区分正文 |
| 上传完成顺序漂移 | 逐张上传，按新增fileid映射，不将并发DOM顺序直接zip文件名 |
| 懒加载图片仍为1×1 | 滚入视口，轮询重新查询的当前节点；旧ElementHandle可能已替换，不改DOM强制加载 |
| 封面仍显示“拖拽或选择封面” | 检查实际背景缩略图和保存版，不只看通用文字 |
| 方形封面裁掉半张脸 | 看新截图、点方形预览并拖动裁切框，每次重截图，不固化本次坐标 |
| 原文/来源复选框点不到 | 用右侧真实.js_article_url_allow_click或.js_claim_source_desc，不强点隐藏input |
| 隐藏reward控件为checked | 核对可见赞赏设置，不从不适用控件推断开启 |
| 保存按钮返回但时间没变 | 比较新增历史版本/回执；旧“已保存”不能当新回执 |
| 准备或上传中断 | 保留rpa-session-state.json，查看原编辑器及图片，不重放非空稿prepare或换目录 |
| 提交后等候发表/审核中 | 保留在途状态并核查发表记录，不当成可重发失败 |
| 提交超时或会话丢失 | submit意图阻止重放，正常登录后查原账号发表历史 |
| 本地blocked、后台已发表 | 从真实后台记录打开公开页核对原稿，再record-published补账 |

验证页不截图落盘，不提取二维码或保存认证URL。用户需要交互的会话启动时加--headed，后台驱动仍隐藏。headless不能显示当前验证二维码；遇到验证保留在途状态，由用户在正常可见后台处理，必要时结束headless后用同一独立profile恢复可见会话、先查结果，不重新提交来生成二维码。

用户明确停止或只维护技能时不操作真实发文。不注册常驻服务、计划任务或Windows登录启动项，不重启网站、采集或其他服务。用户主动打开的浏览器和终端不属于本次RPA清理范围。
