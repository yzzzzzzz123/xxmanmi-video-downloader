# 漫映节目同步操作细则

最新用户要求已统一全部接纳：正常新同步执行[全量节目对齐](../../../references/all-catalogue-sync.md)，包括空记录、失败/raw、历史/旧排除记录、补源和现有分类。不再用下文旧的ack/封面/认可筛选发布范围；旧章节仅用于既有冻结轮重试。全量流程依然保留真实身份、字段哈希、备份、事务及用户数据保护；不伪造历史门禁通过。已有分类、系列及关联保持原样；缺表不自动恢复分类结构，不追加研究或标签写入，不发布无关代码。

当前常规入口：正式workflowctl提交后投递`production_live.py`事件，由主线程授权的有界隐藏CLI持既有单写锁执行delta准备、备份、事务发布和独立生产读取验收；不等待300节目、不用模型逐批同步、不加常驻服务。`production_live.py status`只读，`kick --authorized`仅在存在待办且没有同身份执行器时启动。固定范围内四张节目管理表全部字段、全部关联行和封面哈希都要一致；delta回执不能冒充全库一致。失败保留原包与新事件版本，无差异不重复写入，生产用户数据保留。手动全库校准仍执行`catalogue_align.py prepare/publish --authorized`后`verify`。结构和权限不兼容转交[项目变更发布 Skill](../../manying-project-deploy/SKILL.md)，增量不执行DDL、不部署应用或重启服务。

## 历史冻结轮恢复资料（不是正常新同步规则）

下文只供原100/300冻结轮的原始证据核验；当前运行策略已经将原`production_round.py scan`转到统一计数、`production_round_publish.py`转到全量对齐，并拒绝新建旧筛选轮。不要为了套用下文重建账本或改写旧回执。

## 冻结清单与只读核对

1. 读项目AGENTS.md、节目同步Skill和 [生产增量同步](../../../references/production-sync.md)。授权持续采集时，程序累计四路合格新增、满300通知主线程发布，不等每小时报告；不足300不发布、不逐批让模型扫描全库。一次性同步按用户指定范围冻结，不改持续门槛。仅改规范、只读查询或用户暂停不执行生产。
2. 从已确认、已入库审计、已通过独立封面门禁的结果选择节目。核对详情 URL、节目/资源 ID、封面 SHA-256 和回执；排除 raw、失败、跳过及待复核项。旧节目补源或修正需明确列入，不能默认把历史全库当新增。
   已通过上述门禁的采集结果按清单同步，不再逐部搜索、判断视频内容或核实成人版/播出版；成人向、分级、题材和标题不构成额外发布门禁。封面门禁检查真实帧、图像质量与去重，不承担内容分级审核。
3. 本地导出采用一致性快照，明确字段和节目 ID 清单，只包含 programs、对应 resources 和封面，不导出本地账号、会话或其他用户数据。绑定发布标识、内容哈希和预期新增/更新量，重试复用同一清单。
4. 经严格主机密钥校验的 SSH 检查生产服务、数据库、空间、已有回执与单实例写入锁。记录片库数量、最大 ID、应用版本及生产账号/用户表安全聚合指标，不打印个人数据或令牌。核对网站所需字段与生产结构是否兼容；不兼容时停止合并，将结构变更交给项目发布，不能自行迁移。
5. 没有新增或明确的节目更新时，报告无需同步。生产独有节目、资源和封面不作为差异删除。

## 备份与暂存

历史采集工作目录已由清理 Skill 正式归档时，先用 `production_round.py scan/package` 通过只读归档校验恢复原证据引用；原 owner/work、归档记录/成员大小及原 verification SHA-256 必须一致，不重采或重写旧回执。主线程确认本轮门槛和清单后用 `production_round_publish.py --authorized` 执行，帮助查询和缺授权参数均不进行发布操作。

1. 写入前在生产私有备份目录保存完整数据库 pg_dump -Fc，以 pg_restore -l 验证可读，并保留应用备份/版本记录；联合发布可以复用覆盖两部分的本次备份。备份不放 Web 可访问目录，不拷入仓库。
2. 将数据加载到临时暂存表或隔离 schema，检查行数、外键、重复自然键和实际新增/更新量。节目自然键为 source_url；资源自然键为 (program_id, url_sha256)。
3. 同 programs.id 必须保持相同详情 URL，同详情 URL 必须保持相同 ID；资源同时校验 ID、所属节目和自然键。冲突立即停止，不用覆盖或重编号消除。核对结构后使用明确列清单，不能以整库恢复替代合并。
4. 对既有 scripts/collection/production_sync.py、web/deploy/production_batch.py 与 web/deploy/merge-catalogue.sql.in 检查实际范围、锁、门槛与回执能力。文件存在不证明符合当前规则；.runtime/release/ 历史脚本的旧计数、路径和清单也不能照搬。

## 合并、封面与验收

1. 单个受控事务先合并 programs 再合并 resources，保持原 ID、生产独有行和外键。按 last_seen 单调合并，避免旧快照覆盖更新数据；使用经验证的 identity 插入方法并校正 sequence。事务失败立即回滚，避免活跃请求期间长事务和大范围表锁。
2. 按节目 ID 安装清单内封面：缺失则新增，已有且哈希相同则复用，已有但哈希不同则停止该项并说明冲突。只操作已核验清单，不删除生产独有图片，不将整个本地 runtime 镜像过去。
3. 核对实际新增/更新量、ID 与自然键映射、外键、逐项资源及封面哈希；核对健康接口、列表/详情和播放接口能看到目标节目。目录缓存使用现有刷新机制，本 skill 不以代码切换或服务重启实现刷新。
4. 核对生产账号、会员、会话和用户状态未被导入操作改写；并发用户活动造成的指标变化须与本次写入区分。记录发布标识、清单哈希、逐项结果和生产验收回执；本地 ack 与生产回执分别报告。
5. 失败保留未完成项，重入时验证已成功内容后幂等继续。已出现新的生产用户操作时，不能将整库备份盲目恢复；按本轮事务、清单和备份设计保留新数据的修复。仅节目同步不回滚或替换网页应用。

## 连接与联合发布

当前远端为 ubuntu@43.134.92.99，数据库 manying。优先通过服务器本地 sudo -n -u postgres psql/pg_dump 或 SSH 隧道的最小权限账号操作；远端凭据只在受控进程内读取，不写入命令行历史或同步包。

同时执行两项 Skill 时，按 [项目发布操作细则](../../manying-project-deploy/references/release-procedure.md) 统一冻结本地变更、规划兼容顺序和备份；节目部分仍只写本文件规定的数据。任一部分失败，应分别报告已完成与未完成项，不能把另一部分成功当成完整发布。
