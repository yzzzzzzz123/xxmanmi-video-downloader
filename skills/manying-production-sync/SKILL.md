## 同步范围

**最新规则优先：全部节目数据统一接纳，入库后事件增量同步。** 使用[统一对齐流程](../../references/all-catalogue-sync.md)与`production_live.py`，包括无资源、raw、失败、死数据、历史记录和旧补源；不区分用户/agent认可，旧排除账本不拦截。`program_classifications`已纳入同步；采集状态原样保留，不假报可播放。`catalogue_align.py`保留手动全库校准；旧300冻结轮只用于历史恢复。

本地全部节目管理记录决定范围，不用采集、封面、分类或认可状态筛掉记录。主线程只做技术核验，不逐部审核视频内容或追加题材排除。真实失败/空值原样保存，不假报可播放。

- `programs`、`resources`、`source_observations`、`program_classifications` 全部字段及已有节目封面，包含新增、旧补源、空/失败/raw/死数据。
- 授权持续采集时，数据库提交、补源、搜索提交及封面收尾投递程序事件；主线程授权的有界隐藏CLI合并重复节目，只由一个执行器持锁冻结、备份、事务发布和独立验收。不等待300，不正常唤醒模型，不加常驻服务/定时器；故障保留队列和原冻结包，有界退避后由下次事件或主线程pulse恢复。
- 每轮最多500个真实节目ID，包含所选节目全部关联字段、观察、分类与封面；新事件版本不被旧包成功误清除。增量成功只证明该固定范围，不宣称全库当前一致。用户直接要求全库对齐使用手动全量入口，不恢复暂停采集；仅改规范或查询不执行生产。旧100/300回执保留；不追加分类研究、补标签或系列归组，也没有待开启的分类开关。
- UI 设计、栏目增删、页面文案或其他网站内容、后端逻辑、静态文件、依赖、应用配置、数据库结构及其他项目变更，统一交给 [项目变更发布 Skill](../manying-project-deploy/SKILL.md)。本 skill 不上传应用源码、不安装依赖、不迁移结构、不切换代码或重启网页服务。

## 数据保护与执行

1. 生产是账号、会员、会话、订单、支付、收藏、观看记录和活动数据的权威来源，绝不以本地测试数据覆盖。保留生产独有节目、资源和封面，不整库恢复、不清库、不重跑初装脚本。
2. `programs.id` 与 `resources.id` 跨环境保持含义稳定；同 ID 不同身份或同自然键不同 ID 时停止合并。本地目录字段为权威，真实空值与旧更新也对齐；不同封面哈希按冻结清单备份后替换，不能静默跳过差异。
3. 冻结本轮清单 → 只读核对生产与冲突 → 可恢复的数据库及应用备份/版本记录并验证可读 → 暂存检查 → 单事务受控合并 → 封面安装 → 页面与播放接口验收 → 记录生产回执。
4. 以当前源码检查既有同步器的实际能力；旧脚本、旧打包目录或已有回执不能替代本轮门禁。结构不兼容时停止并转交项目发布，本 skill 不自行迁移。
5. 无差异直接跳过，不发日常报告、不为制造回执写生产。失败保留同一清单与待办，修复需保护新产生的生产用户数据，不盲目恢复整库。任一采集槽位真实故障超过两小时触发项目停止后，不再创建新同步包；已开始的事务安全收尾，未处理事件保留待用户明确恢复。

## 与项目发布联合执行

用户同时要求执行本 skill 和 `manying-project-deploy`，或明确要求将本地所有项目修改同步到生产时，读取并执行两者：本 skill 负责节目、资源和封面，另一 skill 负责其余全部适用于生产的项目变更。使用共同清单与备份，按结构和代码兼容性安排顺序；只有两部分都验收通过，才报告完整同步成功。

“所有修改”覆盖可发布的项目成果，仍保护生产用户数据、凭据与环境专属运行状态。仅要求节目同步时，不隐式调用项目发布。
