# 漫映项目变更发布

本 skill 负责**节目之外的所有项目变更**，适用于已有生产环境的迭代发布。实际执行或设计发布脚本前，读取 [项目发布操作细则](references/release-procedure.md)。仅修改 Skill、开发、诊断或审查时不执行生产发布。

## 发布范围

- UI 设计与交互、栏目增删和排列、页面内容或文案、模板、CSS/JS、其他静态资产。
- 前后端业务代码、接口、新增模块、运行依赖、部署脚本、适用于生产的应用及服务配置。
- 数据库结构的前向迁移、索引、视图、函数、权限，以及栏目定义等网站功能所需的非节目配置/内容数据；后者逐表逐字段明确受控变更，不从本地全表覆盖。
- 项目内其他变更按用途处理：生产运行需要的成果一并交付，开发工具、测试、采集断点和工作日志不装入生产运行目录。生产环境地址、路径与凭据按生产值保留。

新增节目、节目元数据、播放资源和节目封面由 [节目同步 Skill](../manying-production-sync/SKILL.md) 负责。单独执行本 skill 不顺带导入节目；修改封面生成逻辑属于代码发布，传输生成后的节目封面属于节目同步。

## 当前环境与保护边界

- 仓库根目录为本 skill 的上两级。应用源码 web/，结构定义 Datebase/xxmanmi-resource-db/schema.sql 与 web-accounts.sql，部署资料 web/deploy/；以当前实际导入图、页面引用和变更确定完整发布包。
- 当前生产为 Ubuntu ubuntu@example.invalid、数据库 manying、服务 manying.service；应用目录从实际服务配置和版本指针解析，运行数据 /var/lib/manying/runtime、配置 /etc/manying。连接与权限每次核实，通过已核验主机密钥的 SSH 操作；部署密钥从当前用户的 ~/.ssh/manying_deploy 解析。
- 真实账号、会员、会话、订单、支付、收藏、观看记录和活动数据始终以生产为准。代码或结构变更不得导入本地测试用户、重建这些表或丢失已有行；新表必须核对网站账号实际所需权限。
- 发布配置时以生产文件为底合并项目要求的变更，保留生产密钥、域名、路径和环境值；不将本地 .env、.secrets、venv、数据库文件或 runtime 整体覆盖线上。
- 备份后使用经验证的前向结构迁移和保留回退点的代码切换，不执行 install.sh/finish-install.sh 等初装重建流程。网页发布只重启必要的网页服务，不顺带重启采集数据库、采集线程、浏览器或终端。

## 发布闭环

核对当前本地变更与生产差异 → 冻结发布清单 → 相称的本地验证 → 可恢复备份 → 暂存完整应用及依赖 → 必要的前向迁移/配置或内容变更 → 切换应用 → 健康与本次业务功能验收 → 记录版本及结果。

用户要求其他所有修改上线时，按实际差异完整覆盖本 skill 范围，不能只挑入口代码而遗漏新增模块、网页资产、栏目内容或依赖。发现冲突或验证失败时保留回退点，修复后继续；结果明确区分已部署和未完成项。

## 与节目同步联合执行

用户同时要求本 skill 与 manying-production-sync，或明确要求把本地所有项目修改同步到生产时，执行两者，使用同一份总清单和可复用备份。先核对代码、结构与节目数据的兼容关系，再按操作细则安排顺序；完整验收包括项目功能和节目上线两部分。

组合执行覆盖全部适用于生产的本地项目修改，仍保留生产专属用户数据和环境状态。仅要求 UI、栏目或网页内容上线时，不自动扩大到节目同步。
