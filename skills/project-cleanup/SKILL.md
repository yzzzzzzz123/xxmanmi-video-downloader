# 清理 Skill

确认采集线程死亡并需补位时必须调用；其他清理只在用户另行明确要求时执行，不因旧owner数量或文件年龄自行启动。主线程执行，不另外开清理agent。用户本次“全部停用/删除”优先于默认补位：不唤醒、不补开、不采集、不发布；只有明确恢复采集后才重新编组。

日常主线程遵循 [短流程](../../references/main-supervision.md)。**确认死亡后补位必须先调用本Skill清理旧线程，清理验收后才建新UUID；定时轮换完全删除。** 困难优先原线程修复，不把等待、普通错误或浏览器故障伪装成死亡。不安排定期垃圾清理，不重试已取消的旧删除清单；用户后续明确清理请求按新范围执行。主线程修复既有采集故障沿用短流程的最小修复授权，其他开发按该次明确范围执行。不能伪造停写或强行处理在途，保存最小断点，保护健康子线程。只输出正式清理所需的停写证据与验收回执，不增设调试日志、临时脚本或重复快照。

Chrome工作分组名称精确为`01`、`02`、`03`、`04`，禁止“01采集线程”等附加文字。死亡清理还须释放旧线程明确归属、无在途的标签/对象、专属进程和可释放缓存，核对进程实际退出与系统内存；采集者用完本人临时标签且无在途后按浏览器Skill释放。不得因组名、空闲或内存高误关用户/健康线程页面、批杀共享浏览器或清空用户浏览器配置。能力不足保留blocked，不能报彻底清完。

## 最短链路

项目根运行 `python -X utf8 -B skills/project-cleanup/scripts/cleanupctl.py --help`。先 `scan --protect-thread 当前主会话UUID`，完整清单保存到 `.runtime/cleanup/scan.json`，只回传数量与异常。扫描候选不代表已判死。

用户要求全部停用时先 `pause --authorized --apply` 设置持久采集门禁，阻止标准入口继续注册、领批、搜索或收批；它不代替停止已发出的工具/浏览器动作。仅用户后来明确恢复采集才 `resume --authorized --apply`，清理后不得自动解除。

**仅要求暂停时，到设置暂停门禁、定向停止在途执行并保存断点为止**；不继续下方会话删除、owner退役或目录移除步骤，也不为了排空而继续commit/ack。只有用户明确要求相应停用/删除/清理，或运行授权下已核实失效需换新时，才执行适用的清理步骤。不能把暂停或内存告警推断成不可逆删除授权；未知动作保留真实状态，不自行重放。

1. 核实真实 UUID、owner/work 和宿主终态。`idle` / `notLoaded` / 日志不变不单独判死。用户明确全部停止时，定向通知精确采集会话、暂停 goal、保存断点、使用宿主协作中断/停止入口；消息已投递不等于停写。保护主会话、交互终端和其他项目。
2. `session-delete --owner UUID --protect-thread 当前主会话UUID --authorized --apply`：只经正式宿主/CLI入口归档并删除。若普通CLI因当前宿主持有活动子会话而拒绝，且已连接宿主提供 `set_thread_archived`，先对已核实本项目精确子UUID归档，再经CLI删除并核对语义结果及原会话记录；不能误归档主会话，也不因工具缺省threadId而执行。当前宿主入口可用时不要求另装桥接。退出码0不等于成功；删除不可恢复，先保存必要停写/批次摘要，不复制整段聊天。真实能力缺失时保留断点，禁止手删数据库/锁或强杀共享app-server。
3. `retire-owner --owner UUID --evidence STOP.json --authorized --apply`：回执包含 `thread`、`user_authorized=true`、`owner_stopped=true`、非空 `method` / `summary`、全部顶层 NDJSON 的排序 `{name,size,sha256}` 快照。声明必须来自本人确认或宿主终止事实，不能程序假造。默认拒绝在途；明确取消旧任务时加 `--cancel-inflight`，原批次与证据保留，未完项进入待复核，不伪造 captured/ack、不写库或自动重排。
4. 同命令将该 owner 的搜索组合标为 `cancelled_owner_cleanup`，隔离自动重放/交接，原始 claim 和结果留作去重审计；最后在锁内移除活跃 owner，保留防复用记录。跨文件按阶段执行、可重入，失败报告断点，不冒充全成功。
5. `archive-work --owner UUID --authorized --apply --remove-work`：只处理已退役、会话已删且无其他 owner 使用的专属运行目录；验证完整文件快照、压缩包后删除原目录。证据可从 `.runtime/cleanup/archives/` 恢复，原路径索引在回执中。交接目录、数据库/封面目录、未知链接和未停写目录拒绝删除。
6. 再 `scan`：汇报实际会话删除、活跃 owner/在途、归档目录与阻塞数量。历史批次/防复用记录不是活跃线程；未全部验收不能说“彻底清完”。不传 `--apply` 只预检。

证据由程序落盘，模型只读短 JSON；不逐 owner 重读全库/全部会话，不频繁轮询。核验快照发生变化立即停止。身份及断点异常才读取 [协作协议](../../references/multi-thread-collection.md)。清理完成不授权重新采集，补位由仍获授权的主流程执行。

回执准备可用 `prepare-stop --owner UUID`，它只在已核验会话删除时自动生成快照；本人停写确认使用 `--evidence CONFIRMATION.json`（匹配 `thread` 或精确 `owners` 列表及真实停止说明），不代造停写事实。会话与 owner 不同 ID 时暂停并核对映射，不猜 UUID。历史非子会话只在已归档、已退役、明确核对属于本项目采集且不含需保留任务后，才对精确 UUID 追加 `--reviewed-retired-session`；不能用此选项删除活动的用户主会话。

飞书宿主仍持有已停写子会话、普通 CLI 返回拒绝时，先核实本机桥接 `status` 的真实主会话就是受保护的当前主会话。可用已安装桥接的 Python 执行同一命令并加 `--feishu-host`；程序只连接已有认证回环端点，凭据仅进入子进程环境，不落盘或回显，不启动终端、不切换/新建会话、不重启服务。依赖缺失或身份不匹配就报告阻塞，不能猜端点或删除锁。

## 废弃程序、进程与代码

- 用户已长期授权任一采集槽位真实连续故障超过3600秒未恢复时强制停工：复用`scripts/collection/recoveryctl.py stop --authorized --thread <真实主线程UUID>`，先关写闸、保留断点并暂停Goal/中断回合，再由`process_stop.py`终止所属后台采集命令和身份已核验的专属进程，核验退出并写正式回执。此授权不包括删除会话、退役owner、清空存储、删除数据或启动新线程；共享宿主与服务仍保留，不杀当前回执驱动。失败保持闸关闭，不冒充全部停止或重放未知动作。当前用户明确要求强制关闭的占用者另按精确身份处理，不能扩大到所有共享进程。

- 进程核对 PID、启动时间、可执行路径和精确任务关系，避免 PID 复用；不输出含凭据的命令行。优先组件 stop/任务计划 CLI，再按需停止核实的专属 PID；禁止按 `codex/python/node/chrome` 名称批杀。共享浏览器、数据库、Web/relay、桥接/MCP 及其他项目默认保留。
- 对确认废弃的专属自动启动项，保存配置、禁用精确触发入口后再停实例，并核验未重启。不自动卸载软件、删除 Docker 卷/生产数据或改系统代理。Windows 子进程隐藏创建，`exec_command` 使用 `tty:true`。
- 源码用 `git status` / `rg` 查调用、动态入口、任务计划、测试和部署依赖；无静态引用不等于废弃。只删除有明确依据的精确文件，用 `apply_patch` 并运行受影响测试，保留用户未提交修改。禁止 `git clean -fdx` 或按 old/tmp 名称猜删。
- 缓存/产物先列精确清单，校验解析后的绝对路径仍在允许子目录；优先可恢复隔离。递归目标不得是项目根、用户目录、盘根或广泛父目录；链接/归属不明保留并报告。文件清理与进程停止都不得越过用户此次授权范围。
